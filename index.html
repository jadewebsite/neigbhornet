Under the Hood

How the Mesh Works

Every device is simultaneously a sender, receiver, and relay node — building a self-healing network with no central point of failure.

1

Advertise & Discover

Each device continuously advertises a custom BLE service UUID and scans for nearby NeighborNet peers. New devices are discovered automatically within Bluetooth range (~30–100m).

2

GATT Connection & Handshake

When two devices meet, a GATT connection is established. Every device acts as both a GATT server (peripheral) and GATT client (central), enabling bidirectional MeshPacket JSON exchange.

3

Flood Routing with Hop TTL

MeshPackets carry a hopCount and maxHops TTL (default 7). Each relay node increments the counter and forwards to all peers except the sender.

4

De-duplication Cache

Every node tracks a rolling cache of 500 seen packet IDs. Duplicates are silently dropped, preventing infinite relay loops.

5

Firebase Internet Bridge

When internet is available, packets are pushed to Firebase at /relay/<packetId> and delivered via real-time ChildEventListener — no polling. Auto-pruned after 24h.

Technology

Built on Solid Foundations

Modern Android stack designed for reliability, performance, and offline-first resilience.

Kotlin + Jetpack Compose

100% Kotlin codebase with declarative Compose UI and a custom dark brand theme.

BLE GATT Mesh

Custom service UUID with simultaneous advertise + scan + GATT server/client roles on every device.

Room Database

All messages, alerts, and marketplace items persisted locally with Room + type-safe DAOs.

Firebase Realtime DB

Internet relay bridge with real-time push, 24h packet TTL, and automatic pruning on publish.

Coroutines + Flow

SharedFlow for reactive packet delivery. SupervisorJob scopes for crash-isolated mesh services.

Foreground Services

MeshService, SosService, and BootReceiver keep the mesh alive after reboot and in the background.
